📖 2. Premisa del Proyecto

El sistema es un backend asíncrono para un juego de rol de fantasía oscura donde una Inteligencia Artificial ejerce de Dungeon Master (DM). El núcleo del software combina la flexibilidad narrativa de un LLM con la rigidez matemática del documento de referencia del sistema oficial de la quinta edición (SRD 5.2.1). El estado del jugador se persiste localmente para que sus atributos, ubicación e inventario alteren dinámicamente el comportamiento de la IA y el flujo del juego.

📦 3. Stack Tecnológico

  • Lenguaje: Python 3.12+ (Entorno virtual aislado mediante venv).
  • Framework API: FastAPI (Asíncrono, basado en ASGI, documentación interactiva en /docs).
  • Capa de Persistencia (ORM): SQLAlchemy.
  • Base de Datos: SQLite (Archivo local rpg_database.db).
  • Cliente HTTP: HTTPX (Llamadas directas y asíncronas de alto rendimiento).
  • Validación y DTOs: Pydantic v2 (Modelos estrictos de petición y respuesta).

🏗️ 4. Flujo Arquitectónico Actual

El backend opera bajo un patrón de desacoplamiento en dos capas críticas antes de delegar en la IA:

  • Inyección de Contexto Dinámica: Cuando el cliente envía un input, el endpoint interrumpe el flujo, extrae la ficha del personaje desde SQLite mediante su ID y genera un prefijo de metadatos invisible (Ej: [Contexto Jugador: Arthor, Humano Guerrero, HP: 20/20...]) que se fusiona con el prompt del sistema.
  • Autodescubrimiento Determinista de Modelos: Para evitar la deprecación de SDKs oficiales, el backend interactúa mediante HTTP directo con la API v1 de Google Gemini. Al inicializarse, mapea los modelos disponibles en la API Key, autoconfigurándose en producción con el modelo más moderno disponible (Gemini 2.5 Flash), con un fallback hacia gemini-pro si la consulta falla.

📊 6. Modelos de Datos y Endpoints Estabilizados

Ficha de Personaje (SQLAlchemy)

La tabla characters maneja tipos primitivos e híbridos estructurados en JSON elástico:

  • id (Integer, PK) | name (String) | race (String) | char_class (String)
  • level (Integer, default 1) | hp (Integer, default 20) | max_hp (Integer, default 20) | location (String)
  • stats (JSON): Plantilla mutable de características inicializadas algorítmicamente según la clase del personaje (Fuerza, Destreza, Inteligencia, Carisma).
  • inventory (JSON): Lista estructurada para la persistencia de ítems y equipamiento.

Catálogo de Endpoints Operativos

Método Ruta Estructura de Datos e Inferencia
GET / Health check básico. Devuelve el estado del servicio y el ID del modelo de IA seleccionado por autodescubrimiento.
POST /characters Instancia un nuevo personaje basándose en CharacterCreate (Name, Race, Class), calculando sus stats iniciales antes del commit.
GET /characters/{char_id} Extrae la ficha técnica completa del personaje directamente desde SQLite.
POST /chat Recibe el payload narrativo (Message, Character_id, History). Ejecuta la inyección de metadatos y retorna la respuesta limpia del DM.

🎲 7. Integración Normativa: D&D 5e SRD

La IA debe regirse estrictamente bajo el núcleo matemático y terminológico oficial en español extraído del SRD 5.2.1:

  • Ecuación de Modificadores: Derivada directamente de la puntuación de característica: Modificador = (Puntuación - 10) // 2 (redondeado hacia abajo). Ej: Fuerza 14 = +2.
  • Escala de Dificultad (CD): Muy Fácil (5), Fácil (10), Media (15), Difícil (20), Muy Difícil (25), Casi Imposible (30).
  • Comportamiento del DM en Conversación: Ante cualquier acción arriesgada descrita por el jugador, la IA **no debe resolver el resultado**. Debe pausar la narración en el clímax e indicar la característica oficial requerida (Ej: "Tratas de forzar los goznes de hierro... Por favor, realiza una prueba de Fuerza (Atletismo)").
