🏗️ 2. Premisa y Flujo de Datos

El sistema es un backend asíncrono donde una IA actúa como Dungeon Master (DM) interactivo. Fusiona la narrativa libre con las matemáticas de D&D 5e (SRD 5.2.1), persistiendo el estado del personaje en local.

  • Inyección de Contexto: Las peticiones al endpoint de chat interceptan el ID del jugador, recuperan su ficha técnica en SQLite e inyectan un prefijo invisible de metadatos (Ej: [Contexto Jugador: Arthor, Humano Guerrero, HP: 20/20...]) en el prompt que va a la IA.
  • Autodescubrimiento Determinista de Modelos: El backend utiliza HTTPX para atacar directamente la API v1 de Google Gemini, evitando SDKs inestables. En el arranque, mapea los modelos con soporte generateContent y se autoconfigura con el más moderno (Gemini 2.5 Flash), usando gemini-pro como fallback.

🛣️ 4. API Gateway: Catálogo de Endpoints Activos

Todos los esquemas de entrada y salida están tipados de forma estricta mediante Pydantic v2:

  • GET /: Health check. Confirma el estado del servicio y el ID de la IA activa.
  • POST /characters: Instancia un personaje en la DB computando sus estadísticas iniciales por clase.
  • GET /characters/{char_id}: Recupera la ficha técnica completa del jugador desde SQLite.
  • POST /chat: Procesa el mensaje del usuario con inyección sutil de contexto y devuelve la narrativa pura de la IA.
